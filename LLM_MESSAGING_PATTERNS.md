# LLM + Messaging Workflow Patterns

This document demonstrates successful patterns for integrating LLM nodes with messaging systems in flowsh workflows.

## 🔧 Key Technical Fix: LLM Node Standard Variables

**Problem Solved**: LLM nodes now create standard workflow variables that other nodes can reference, similar to how HTTP nodes create `http_response_body`.

### LLM Node Output Variables

- `llm_content` - The generated content from the LLM
- `llm_success` - Boolean indicating successful generation

### Usage Pattern

```yaml
- id: 'generate_text'
  type: 'llm'
  data:
    title: 'Generate Content'
    prompt: 'Write a creative message'

- id: 'process_content'
  type: 'variable-assignment'
  data:
    variable: 'formatted_message'
    value: 'AI says: ${llm_content}' # ✅ This now works!
```

## 🚀 Working Pipeline: LLM → Variable Assignment → Messaging

### Simple Pattern

```yaml
workflow:
  name: 'llm-to-message'
  description: 'Generate content and format for messaging'

graph:
  nodes:
    - id: 'generate'
      type: 'llm'
      data:
        prompt: 'Write a haiku about artificial intelligence'

    - id: 'format'
      type: 'variable-assignment'
      data:
        variable: 'message'
        value: |
          🤖 AI Haiku 🎋

          ${llm_content}

          ✨ Generated by flowsh

    - id: 'send'
      type: 'telegram' # or 'code' for testing
      data:
        message: '${message}'

  edges:
    - source: 'generate'
      target: 'format'
    - source: 'format'
      target: 'send'
```

## ✅ Two-Stage LLM Fallback System

The LLM nodes include automatic fallback:

1. **OpenAI API** (if `OPENAI_API_KEY` set)
2. **LLMv7 API** (no key required)
3. **Mock response** (for testing)

### Benefits

- **No API keys required** for basic testing
- **Reliable execution** even without external API access
- **Production-ready** with proper API keys

## 📊 Standard Node Variables by Type

| Node Type             | Standard Variables                         | Example Usage           |
| --------------------- | ------------------------------------------ | ----------------------- |
| `llm`                 | `llm_content`, `llm_success`               | `${llm_content}`        |
| `http-request`        | `http_response_body`, `http_response_time` | `${http_response_body}` |
| `variable-assignment` | User-defined variable name                 | `${my_variable}`        |

## 🎯 Best Practices

### 1. Use Standard Variables

- Always reference `${llm_content}` not `${node_id}`
- Check available standard variables for each node type

### 2. Simple Prompts First

- Start with static prompts for testing
- Add dynamic variables after basic flow works

### 3. Test with Mock Nodes

- Use `code` nodes with `echo` for testing message formatting
- Replace with real messaging nodes after verification

### 4. Variable Assignment for Formatting

- Use `variable-assignment` nodes to format complex messages
- This provides clear separation between content and presentation

## 🔧 Implementation Details

### LLM Node Generator Changes

```typescript
// Now creates standard workflow variables
set_workflow_var "llm_content" "$llm_content"
set_workflow_var "llm_success" "true"

// getVariables() now returns output variables
const outputVars = ['LLM_CONTENT', 'LLM_SUCCESS'];
return [...templateVars, ...outputVars];
```

This enables the variable registry to properly track and validate variable dependencies between nodes.
